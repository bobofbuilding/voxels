# Install with an AI assistant

Give an assistant with terminal access this prompt:

> Help me host a Voxels world node from https://github.com/bobofbuilding/voxels. Read AGENTS.md and selfhost/node/README.md from a trusted checkout. Inspect my OS, available memory, storage, Node and Docker before changing anything. Ask whether I want a separate starter world or to join an existing shared world. For a shared world, obtain the public network administrator wallet, preserved parcel roles, pinned world ID, verified initial archive and at least one HTTPS peer. Use selfhost/node/setup.mjs to create a new private node directory and start the services. Never request my wallet private key or seed phrase. Keep the database on local storage and the archive on my chosen storage. Verify local health and preserve all existing data. Prepare public HTTPS routing separately and explain the exact DNS or firewall changes before applying changes I have not already authorized. Report what works, what was tested and anything still required.

## Operator checklist for the assistant

1. Read local repository instructions. Inspect existing services and ports. Do not stop unrelated applications or containers. Do not run a remote shell installer blindly. Install missing prerequisites only with the user's authorization.
2. Confirm full versus partial coverage (and selected parcel IDs for partial nodes), starter versus shared-world mode, a new private data directory, public network administrator address, and optional hostname. Do not infer a network identity from a hostname alone. A third-party host cannot authorize new editors.
3. Verify the downloaded archive using the publisher key and manifest hash pinned in a trusted repository revision. Reject missing, corrupt or non-public data. Do not replace an existing database with an archive. The inventory requires current `builds/` plus reviewed `islands.json`; saved versions remain archival.
4. Run `doctor`, `init`, then `up` with the documented arguments. Keep configuration and logs containing credentials private. Do not print secrets, commit them, or send them to a chat service. The installer generates service credentials and a node-signing key locally; the owner wallet remains in its wallet application.
5. Check `/health`, `/api/ping`, `/federation/info` and `/play`. Confirm the reported world/administrator against trusted configuration and verify the archived parcel roles were preserved. Inspect container health without dumping environment variables. A starter being healthy does not prove it has joined the public world.
6. Configure only the user's authorized HTTPS route to the loopback gateway. Preserve unrelated DNS and firewall rules. Confirm HTTPS and both WebSocket routes. Do not expose PostgreSQL, Redis, Docker, SSH or a storage administration interface to the public as a shortcut.
7. Use a dedicated disposable world and throwaway wallet for synchronization tests. Confirm two hosts accept edits independently, converge after reconnection, reject forged edits and remove departed players. Do not modify public parcels as test fixtures. Ask the operator to sign through their wallet for the intended production editing check; never extract its key.
8. Record the source revision, public world ID, peer URLs and private data location in the operator's local notes. Explain backup, restart and upgrade procedures, current parcel roles, pending permission conflicts and protocol limits. Do not claim a live deployment or successful wallet check without evidence.

The installer never deletes retained database files. An archive directory requires a real filesystem quota configured separately; a folder name or application budget does not reserve capacity. Do not create destructive retention schedules without an explicit request.

For a full public-media download, use [the standalone media archive installer](../media/README.md). It keeps payloads on archive storage, queues the smallest measured type groups first, and provides a portable catalog and progress reports.
